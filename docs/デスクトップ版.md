# デスクトップ版(Tauri)の作り

専用の窓(`CoilCalculator.exe`)で動きます。**ポートを使いません。**
ブラウザ版(`Start.vbs`)は予備として残してあります。土台は
[python-web-tools](https://github.com/ViVio-Hellon/python-web-tools)(梱包資材総合ツール)の
デスクトップ版と同じで、このツールに合わせて次を変えています。

| | python-web-tools | このツール | 理由 |
|---|---|---|---|
| 画面のファイル | Python が返す | **Rust がディスクから返す** | 画面は静的なファイルだけ。three.js(600KB)を標準入出力に通さない |
| Python に渡すもの | すべての要求 | `/api/…`(計算)だけ | 同上 |
| Python の部品 | Flask + waitress | **標準ライブラリだけ** | ラインPCに追加のパッケージを入れられない。経路が数本なので振り分けは表で足りる |
| 起動の合言葉 | あり | なし | 標準入出力は親子だけの通り道で、こちらの Python はほかに口を持たない |
| ブラウザ版との関係 | — | **同時に動かさない(後から開いたほうが止まる)** | 依頼による |

## 要求の流れ

```
窓(WebView2)
  │  app://localhost/…(Windows は http://app.localhost/…)── ネットワークを通らない
  ▼
外枠(Rust)main.rs::handle
  ├─ /api/… ──▶ bridge.rs ──標準入力──▶ bridge.py ──▶ coilcalc.web.App.handle ──▶ calc.py
  │                         ◀─標準出力──
  └─ それ以外 ──▶ static_files.rs(app/static/ の中だけ。`..` は通さない)
```

ブラウザ版は同じ `coilcalc.web.App.handle` を `http.server` から呼びます。
**計算・範囲・丸め・表示の文字は、どちらの版でも同じ関数を通ります。**

## ブラウザ版との排他

```
%LOCALAPPDATA%\CoilCalculator\runtime\instance.lock   OS のファイルロック
%LOCALAPPDATA%\CoilCalculator\runtime\instance.json   いま握っているのは誰か(版・pid・URL)
```

- デスクトップ版(Rust `instance.rs`)は `LockFileEx`(ファイル全体)、ブラウザ版(Python
  `instance_lock.py`)は `msvcrt.locking`(先頭1バイト)。範囲が重なるので互いに取れない
- 錠を取れなかった側が `instance.json` を読んで、誰が動いているかを知らせて止まる
- 錠は OS が持つので、落ちても残らない(次に開いたほうが取れる)
- 作業フォルダの決め方は Rust と Python で同じ(`tests/test_instance_lock.py` が突き合わせる)
- 試験(`COIL_TOOL_QUIET=1`)ではダイアログを出さずに終了コード 3 で終わる

## 動きの約束

| 場面 | 動き |
|---|---|
| 起動 | 窓がすぐ出る(画面のファイルは Rust が返す)。計算は Python の受け付けが始まりしだい |
| もう1つ起動しようとした | 新しく起動せず、開いている窓を前に出す(single-instance。使えない環境でも錠で止める) |
| ブラウザ版が動いている | 「ブラウザ版が動いています」を出して終わる |
| Python が見つからない・起動できない | 理由と次にすること(Python の入れ方)・ログの場所を窓に出す |
| Python が途中で落ちた | 窓を読み直して理由の画面を出す |
| 窓の × | 終わる。標準入力が閉じるので Python も終わる(取り残さない)。操作説明書の窓が開いていても全部終わる |
| 印刷 | 画面の「印刷」→ WebView2 の印刷ダイアログ(計算書は画面と同じ文字) |
| 操作説明 | 画面の「操作説明」→ 外枠の `open_manual` が別の窓(`manual`)で説明書を開く。開いていればその頁へ移して前に出す。開ける頁は `index` `coil` `plate` だけ |
| 版 | 窓の題名に「v1.1.0」。画面の版の詳細に外枠の版(応答の見出し `X-Coil-Shell-Version`)・Python の版(`/api/health`) |

画面から外枠に頼めるのは `open_manual` だけです(`capabilities/default.json`。画面は `app://` で返す
ファイルなので `remote` に宛先を書く。python-web-tools と同じ形)。

Python は**同梱しません**。各PCに入っている Python を使います(`python.exe` → `py.exe -3` の順に探す。
`COIL_TOOL_PYTHON` で指定もできる)。追加のパッケージは要りません。

## 作り方

**Windows 版は GitHub Actions が作ります**(`.github/workflows/desktop-windows.yml`)。
push のたびに Python の試験(Windows・Python 3.8)・Rust の試験・exe の作成・exe を起動しての確認まで流れ、
成果物 `CoilCalculator-windows` に `CoilCalculator.exe` が入ります。
配るときは exe をアプリのフォルダの**直下**(`bridge.py` と同じ場所)に置きます。

手元で作るとき(開発機):

```
cd src-tauri
cargo build --release            # target/release/CoilCalculator(.exe)
python ../scripts/desktop_smoke.py --exe target/release/CoilCalculator    # Linux は xvfb-run を前に付ける
```

Linux で作るには WebKitGTK が要ります(`libwebkit2gtk-4.1-dev` など)。Rust は 1.89 以上。

## 置き場所の決まり

- exe は `bridge.py` と同じフォルダに置く(上の階層もたどるので、`src-tauri/target/...` から動かしても見つかる)。
  `COIL_TOOL_ROOT` で指定もできる
- 版は `config/app.json`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` の3か所。食い違うと試験が落ちる
- アイコンは `scripts/make_desktop_icon.py` で作る(標準ライブラリだけ。`src-tauri/icons/`)

## 確かめきれていないこと(Windows の実機で見る)

窓を実際に動かした確認は Linux(WebKitGTK)で行いました。Windows では GitHub Actions が
「起動して計算が返る・待ち受けない・止めたら Python も終わる・ブラウザ版との排他(両方向)」まで確かめます。
次は**実機で人が見る**必要があります:

- 「印刷」から実際に紙が出ること(WebView2 の印刷ダイアログ)
- ラインPCで 3D(WebGL)が出ること(出ない PC では、元どおり「3D表示を使えません」と出て計算とグラフは使える)
- ブラウザ版が開いているときにデスクトップ版を開いたダイアログの見え方
