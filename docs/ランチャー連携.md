# 業務ツール統合ランチャーとの連携

[業務ツール統合ランチャー](https://github.com/ViVio-Hellon/python-business-tools-launcher)(以下 ランチャー)から
このツールを起動・切り替え・停止するための、**ツール側の取り決め**です(ランチャー連携 要件定義の
「3. 各ツール側への依頼」「10. 起動完了の確認」)。

- 作法は統合ツール([all-tools](https://github.com/ViVio-Hellon/all-tools) の `docs/ランチャー連携.md`)と揃えています。
  違うところは「6. 統合ツールとの違い」にまとめました
- 確かめたランチャーの版: **1.7.0**(`a842252`。ツール側の入口を優先して使う版)と 1.6.4(`621a7fe`)
- 試験: `tests/test_launcher.py`(ランチャーのリポジトリが手元にあれば**ランチャー本体のコード**で
  登録の読み取り・入口の見つけ方・起動確認・停止まで流す)・`tests/test_launch_windows.py`(入口の bat を
  ランチャーと同じ呼び方で動かす)・`scripts/desktop_smoke.py` の 10(exe を入口で確かめて止める)。
  Windows の CI はランチャーを取ってきて流します

## 1. 起動ファイル(要件 3.1・3.3)

| 起動ファイル | 中身 | 画面 | 使うとき |
|---|---|---|---|
| **`CoilCalculator.exe`** | デスクトップ版(Rust/Tauri の窓)。計算の Python を自分で起こす。**ポートを使わない** | ツール自身の窓 | **ふだんはこれ** |
| `Start.vbs` | ブラウザ版(予備)。`pythonw start_app.py` を起こして**すぐ戻る**。引数は渡す(下) | ランチャーの専用画面(`--no-browser` が届く)/ ダブルクリックならふだんのブラウザー | exe が使えない PC |
| `start.bat` | ブラウザ版の診断用の入口。`python start_app.py %*`(止まるまで戻らない。最後の `pause` はランチャーから呼べば素通り) | Start.vbs と同じ | 起動しないときの原因調べ |

どれも、ダブルクリックでも、ランチャーから直接実行しても同じように起動します。exe から先
(錠・作業フォルダ・VC計算マスタの用意・Python の起動)はツールが受け持ちます。

- 1台の PC には **exe か Start.vbs のどちらか1つ** を登録します(同じアプリID `nlm.coil-calculator` は
  2行にできません。デスクトップ版とブラウザ版は同時には動きません)。PC ごとに配布先設定で選びます
- 終了コード(start.bat / start_app.py): 0 = 終わった・すでに動いていた画面を案内した / 1 = 起動できない /
  3 = もう一方の版(デスクトップ版)が開いているので起動しなかった

## 2. ツール側の入口(ランチャー 1.7.0〜。要件 3.2・3.5・3.6・10)

起動ファイルと同じフォルダ(アプリのフォルダの直下)に置いてあります。ランチャーは、これがあれば
**自分の推測(ポートでの確認・窓の検出・停止方法の自動選択)より優先**して使います。exe を選んだ PC でも
Start.vbs を選んだ PC でも、同じ入口が使われます。

### launcher_check.bat(起動確認の入口)

```
launcher_check.bat  →  python process_manager.py --check
終了コード  0 = 使える / 2 = 準備中 / 1 = 動いていない     最後の1行 = 今の様子
```

| 動いているもの | 答え |
|---|---|
| デスクトップ版 | 0「デスクトップ版(CoilCalculator.exe) が動いています」 |
| ブラウザ版(`/api/health` が app_id 一致・`ready: true`) | 0「ブラウザ版が使えます(http://127.0.0.1:8741/)」 |
| ブラウザ版(錠は取ったが、まだ答えない) | 2「ブラウザ版を準備しています」 |
| どちらも動いていない(落ちて残った印は、その pid がもういないので数えない) | 1「動いていません」 |

**錠を取りにいきません**(錠の隣の `instance.json` と、その pid が生きているかだけを見る)。
ランチャーは起動を待つあいだ毎秒これを呼ぶので、錠を試しに取ると、ちょうど起動しようとしている版が
「もう一方が動いている」と止まってしまうためです。

### launcher_stop.bat(終了の入口)

```
launcher_stop.bat  →  python process_manager.py(stop.bat と同じ。pause は無い)
終了コード  0 = 止めた / 1 = 止めなかった(最後の1行が理由)
```

- **デスクトップ版もブラウザ版も、確かめを出さずに止めます**
  - ブラウザ版: `POST /api/shutdown {"force": false}`
  - デスクトップ版: ポートが無いので、錠の隣に `stop.request` を置いて exe の pid 宛てに頼む。
    Python が見つけて「終了」と同じ止め方で止まり、exe も一緒に終わる(`coilcalc/stop_request.py`)
- VC計算マスタへ書いている最中なら、**書き終えてから**止まります。終わらなければ 1 と
  「VC計算マスタへの書き込みが終わらないため、止めませんでした」。ランチャーはこれを利用者に出し、
  強制終了を選んだときだけ、ランチャーの止め方(`stop.bat --force` など)で続けます
- 止まったかどうかは、ランチャーが launcher_check.bat で確かめます
- **ほかのツールの Python・exe には触りません**(頼みは錠の持ち主の pid 宛て)

## 3. 入口が無いとき(ランチャー 1.6.4 まで)の受け口

1.6.4 までのランチャー、または入口を消したときは、ランチャーの推測で動きます。そのための受け口も
統合ツールと同じ形で持っています。

| 受け口 | 中身 |
|---|---|
| `GET /api/health`(ブラウザ版) | `{"app_id": "nlm.coil-calculator", "ready": true, "stage": "使えます", "pid", "port", "app_root", "version", ...}` |
| `POST /api/shutdown {"force": false\|true}` | 200 `{"stopped": true}` / 409 `{"reason": "busy", "running": ["VC計算マスタへの書き込み"]}`(force でないとき) |
| `stop.bat` | launcher_stop.bat と同じ(どちらの版も止める)。`--force` で待たずに止める |
| 窓に「閉じて」(× と同じ) | 「終了しますか?」の確かめが出る(× と区別できないため) |

## 4. 登録(config/app.json)とランチャーの設定

ランチャーは起動ファイルの近くの `config/app.json` から **アプリID・表示名・版・ポート**を読みます。
ポート(`server.port` = 8741)はブラウザ版のものです(統合ツールと同じく app.json に書いています)。

| 起動ファイル | 画面 | ポート | 起動引数 | 止め方 |
|---|---|---|---|---|
| `CoilCalculator.exe` | アプリの窓(exe を選ぶと自動で決まる) | 入ったままでよい(入口が確かめる) | 空 | 自動(入口が使われる) |
| `Start.vbs` | ブラウザー(自動) | 8741(app.json から入る) | `--no-browser`(ランチャーが自動で入れる) | 自動(入口が使われる) |

- **1.6.4 までのランチャー**では、exe の行のポートを空にしてください(統合ツールと同じ)。入ったままだと、
  起動は正しくできますが、ランチャーが /api/health を見回って「応答しません」と1回知らせます。
  停止方法を「stop.bat」にすると、切り替えのたびの「終了しますか?」が出ません
- ブラウザ版は 8741 がふさがっていると 8742〜 を使います。そのときランチャーは 8741 の画面を開くので、
  8741 を空けるか、app.json の `server.port` とランチャーのポートを同じ空いている番号にしてください

## 5. 起動完了の確認(要件 10)のまとめ

| ランチャー | デスクトップ版 | ブラウザ版 |
|---|---|---|
| 1.7.0〜(入口あり) | launcher_check.bat が 0 | launcher_check.bat が 0(2 の間は待つ) |
| 1.6.4 まで | 窓が出たこと | `/api/health` の app_id 一致・`ready: true` |

## 6. 統合ツール(all-tools 1.2.0)との違い

| 項目 | 統合ツール | このツール | 理由 |
|---|---|---|---|
| ツール側の入口(1.7.0) | まだ無い(1.2.0 は 1.7.0 より前) | launcher_check.bat・launcher_stop.bat | ランチャー 1.7.0 の正式な作法。統合ツールにも同じ入口を足すと揃う |
| stop.bat とデスクトップ版 | 止めない(戻り値 1。窓を前に出す) | 止める(確かめ無し) | このツールの窓には置いておく打ちかけが無い(入力した値は保存しない道具)ので、確かめ無しで止めてよい |
| Start.vbs の引数 | 渡さない(ふだんのブラウザーで開き、画面の打ちかけを置く頼みを必ず通すため) | 渡す(ランチャーの専用画面で開き、切り替えのとき閉じる) | 画面に置いておく打ちかけが無いので、閉じられても失うものが無い |
| 停止要求の 409 | asking / refused / busy | busy だけ | 画面に訊くこと(打ちかけ)が無い |
| 停止要求のトークン | `X-Tool-Token`(portal.lock) | 使わない(127.0.0.1 からだけ受ける・よその画面からの要求は断る) | 以前からの作り |
