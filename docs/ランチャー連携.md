# 業務ツール統合ランチャーとの連携

[業務ツール統合ランチャー](https://github.com/ViVio-Hellon/python-business-tools-launcher)(以下 ランチャー)から
このツールを起動・切り替え・停止するための、**ツール側の取り決め**です。
ランチャーはツールごとに分岐しないので、このツールの側がランチャーの作法に合わせています。

試験: `tests/test_launcher.py`(ランチャーのリポジトリが手元にあれば、**ランチャー本体のコード**で
登録の読み取り・起動確認・停止まで確かめる)・`tests/test_launch_windows.py`・`scripts/desktop_smoke.py` の 10。
Windows の CI はランチャーを取ってきて流します。

## 1. 起動の入口(要件 3.1・3.2・3.3)

| 起動ファイル | 版 | ランチャーでの扱い | 直接ダブルクリック | 推奨 |
|---|---|---|---|---|
| `CoilCalculator.exe` | デスクトップ版(専用の窓) | 「アプリの窓」(Tauri と見分ける)。起動と生死は窓とプロセスで見る | できる | **◎ ふだんはこれ** |
| `start.bat` | ブラウザ版 | ランチャーが `--no-browser` を渡し、自分の窓で `http://127.0.0.1:8741/` を開く。切り替えのとき閉じる | できる(黒い窓に原因が出る) | ○ exe が使えない PC |
| `Start.vbs` | ブラウザ版(黒い窓なし) | 引数を渡す(`WScript.Arguments`)ので start.bat と同じに使える | できる | △ start.bat を推奨 |

- どれも**それだけで起動が完結**します(ランチャー無しでダブルクリックしても同じに動く)。
  中の処理(錠・作業フォルダ・VC計算マスタの用意・ポートの選び直し)はツールの中で行います
- **同じ PC で同時に動くのはどちらか1つ**(デスクトップ版とブラウザ版は排他)。ランチャーの1行に
  登録するのも、どちらか1つにしてください(アプリID が同じ `nlm.coil-calculator` なので、2行は登録できません)
- 終了コード(start.bat / start_app.py)

  | コード | 意味 |
  |---|---|
  | 0 | 終わった / すでに動いていたので、その画面を案内して終わった(2つ目を起こさない) |
  | 1 | 起動できなかった(Python が無い・画面のファイルが無い・ポートが全部ふさがっている など) |
  | 3 | もう一方の版(デスクトップ版)が開いているので起動しなかった |

## 2. 登録(config/app.json)

ランチャーは起動ファイルの近くの `config/app.json` から **app_id・表示名・版** を読みます(手で写させない)。

```json
{ "app_id": "nlm.coil-calculator", "display_name": "VC長さ・コイル平板 計算ツール", "version": "2.1.0", ... }
```

**`server.port` は app.json に書いていません**(既定の 8741 はプログラムの中)。
ランチャーは exe を登録するときも app.json のポートを拾い、拾うと「/api/health で起動を確かめる行」に
なります。デスクトップ版はポートを持たないので、90秒待って「起動できませんでした」になってしまいます。

| 登録する起動ファイル | 設定画面でのポート | 画面 |
|---|---|---|
| `CoilCalculator.exe` | **空のまま** | アプリの窓(自動で選ばれる) |
| `start.bat` / `Start.vbs` | **8741** を入れる(空だと保存時に「ポートが要ります」と出る) | ブラウザー(自動) |

ブラウザ版はふだん 8741 で待ち受けます。8741 がほかのアプリにふさがっていると 8742〜 を使うので、
そのときはランチャーの起動確認が通りません(ランチャーの記録に「起動できませんでした」と出る)。
8741 を空けるか、`config/app.json` に `"server": {"port": 空いている番号}` を書き、ランチャーにも同じ番号を入れてください。

## 3. 起動完了の確認(要件 10)

| 版 | ランチャーが見るもの |
|---|---|
| デスクトップ版 | 窓を持つプロセス(exe)が生きているか |
| ブラウザ版 | `GET http://127.0.0.1:8741/api/health` が `app_id` 一致・`ready: true` を返すか |

```json
GET /api/health
{ "ok": true, "app_id": "nlm.coil-calculator", "display_name": "…", "version": "2.1.0",
  "mode": "browser", "ready": true, "stage": "使えます",
  "pid": 1234, "port": 8741, "app_root": "D:\\ツール\\CoilCalculator", ... }
```

- `ready` は、待ち受けを始めた時点で `true`(VC計算マスタは画面を開いてから読むので、待たせない)
- `pid`・`app_root` はランチャーが止めるときに相手を確かめるのに使います(ほかのプロセスを落とさない)

## 4. 停止(要件 3.5・3.6)

ランチャーの停止の順(停止方法「自動」):

```
デスクトップ版(アプリの窓)   ① 窓に「閉じて」(× と同じ)② stop.bat ③ pid
ブラウザ版                   ① stop.bat ② POST /api/shutdown {"force": …} ③ pid
```

### stop.bat(専用の終了入口。どちらの版も止める)

```
stop.bat            止める。確かめは出さない。VC計算マスタへ書いている最中なら書き終えてから止まる
stop.bat --force    待たずに止める(書く取引は途中で止まっても元に戻るので、マスタは壊れない)
stop.bat --status   何が動いているかを出すだけ
戻り値              0 = 止まった / もともと動いていない、1 = 止まらなかった
```

| 動いているもの | stop.bat がすること |
|---|---|
| ブラウザ版 | `POST /api/shutdown {"force": false}`(書き込み中なら 409 で断られる)→ 止まらなければ下と同じ頼み方 |
| デスクトップ版 | ポートが無いので、錠の隣に **`stop.request`** を置いて頼む(錠を握っている exe の pid 宛て)。Python が見つけて「終了」と同じに止まり、外枠(exe)も一緒に終わる |
| `--force` で、頼んでも止まらない | 錠を握っている pid を止める(錠を握っているのはこのツールだけなので、ほかのプロセスは落とさない) |

- **ランチャーの「窓に閉じて」(× と同じ)では「終了しますか?」の確かめが出ます**(× を押したのと
  区別できないため)。10秒答えないと、ランチャーは「終了の確認」と出して止めません。
  切り替えのたびに確かめを出さないなら、ランチャーの設定でこの行の**停止方法を「stop.bat」**にしてください
  (確かめ無しで閉じる)
- `POST /api/shutdown {"force": false|true}` はランチャーの停止要求の形です。書き込み中は
  `409 {"stopped": false, "reason": "busy", "running": ["VC計算マスタへの書き込み"]}` を返し、
  ランチャーは止めずに「実行中の処理があります」と出し、利用者が［強制終了］を押したときだけ `force: true` で送り直します。
  画面の「終了」・窓の ×(`{}` / `{"confirmed": true}`)は今までどおり確かめを通ります

## 5. ランチャーの側へ(申し送り)

ツール側だけでは避けられないもの。ランチャーの直しどころの案です。

1. **Tauri と見分けた exe では app.json のポートを拾わない**(`tool_registry.probe_tool_folder`)。
   いまはこのツールが app.json にポートを書かないことで避けています。ほかのツールで
   「中に Web サーバーを持たない Tauri の exe」と「同じフォルダのブラウザ版」が並ぶと同じことが起きます
2. **stop.bat の戻り値 1 を「止まらなかった」と早めに受け取る**。いまは戻り値を記録だけして、
   停止の待ち時間(既定 30 秒)いっぱい待ってから次の手へ進みます
3. 「アプリの窓」の停止の既定(窓に「閉じて」が最初)は、× に確かめのあるツールでは切り替えのたびに
   確かめが出ます。アプリの窓の行でも、stop.bat があれば先に使う、という順も考えられます
